## 0. 언어 표준

- **ANSI C (C89 / ISO C90)** 기준으로 작성된 강의 자료
- 코드 예시에 C99 이상의 문법이 사용되면 오류로 간주
  - `//` 단행 주석 사용 불가 → `/* */` 만 허용
  - `for (int i = 0; ...)` 형태의 선언 불가 → 반드시 블록 선두에 분리 선언
  - `_Bool`, `inline`, `restrict`, `<stdbool.h>` 등 C99 전용 키워드·헤더 사용 불가
  - 가변 길이 배열(VLA) 사용 불가
- 코드 스타일은 TCPL(The C Programming Language, Kernighan & Ritchie) 스타일을 따름

## 2. 괄호 위치 규칙

### 2-1. 함수 호출 — 함수명과 여는 괄호 사이 공백 금지

```
/* 잘못된 예 */
printf ("Hello\n");
getchar ();

/* 올바른 예 */
printf("Hello\n");
getchar();
```

- 매크로도 동일하게 적용: `sizeof(int)` O, `sizeof (int)` X

### 2-2. 설명 문장 내 괄호 — 앞 단어와 붙여 쓰기

```
/* 잘못된 예 */
`printf` 함수 (표준 입출력)를 사용

/* 올바른 예 */
`printf` 함수(표준 입출력)를 사용
```

- 영어 단어, 한글 단어, 코드 inline 모두 뒤에 오는 `(` 는 공백 없이 붙임
- 예외: 문장 맨 앞에서 독립적으로 쓰인 `(note)`, `(NB)` 류는 허용

### 2-3. 조사 앞 괄호 생략 시 문장 매끄러움

- 괄호 내용을 생략했을 때도 조사가 자연스러워야 함
- 기준: 괄호 바로 앞 단어(또는 코드 명칭)의 발음 끝 받침으로 조사 결정

```
/* 잘못된 예 */
`for` 문 (반복문)은 → 괄호 생략 시 `for` 문은 → OK
`int`형 (정수 타입)을 → 괄호 생략 시 `int`형을 → "형을" 이 아닌 "타입을" 로 교정 필요
```

### 3-3. 자주 틀리는 패턴

- `~은/는` vs `~이/가`: 주제·대조는 은/는, 주어는 이/가
- `` `else`가 `` — "엘스" → 끝 받침 ㅅ → 주격은 `이`, 하지만 `else` 뒤에 주격조사가 오면 `else`가 아닌 `else`이 → 구어 발음 기준 관용적으로 `가` 허용 시 표기 일관성 유지 필요
- `` `NULL`을 `` — "널"의 받침 ㄹ → 목적격: `를` 이 아닌 `을` ← 단, ㄹ 받침은 목적격 **`를`** 사용 → `NULL`을 → 잘못됨, `NULL`를 → OK

> **참고**: ㄹ받침 목적격은 `를`이 올바른 형태.

## 4. 마크다운 서식 규칙

### 4-1. 프로그래밍 전용 용어 — 이탤릭

다음 용어들은 설명 문장(description text)에서 backtick 이 아닌 이탤릭(`*term*`)으로 표기합니다.  
코드 블록 내부(```` ``` ```` 사이)는 적용하지 않습니다.

| 용어 | 표기 |
|---|---|
| lvalue | `*lvalue*` |
| rvalue | `*rvalue*` |

### 4-2. 코드·식별자 — 인라인 코드(backtick)

- 키워드(`int`, `for`, `while`, ...)
- 함수명(`printf`, `malloc`, ...)
- 변수명, 매크로명
- 파일명(`stdio.h`, `limits.h`, ...)
- 변환 지정자(`%d`, `%f`, ...)
- 연산자 그 자체 (`+=`, `!=`, ...)

### 4-3. 표 내 열 헤더

- 프로그래밍 용어 열 헤더도 backtick 처리: `| \`lvalue\` | \`rvalue\` |`

### 4-4. 수식 — KaTeX

- 수학 공식, 시간 복잡도 등 수식은 인라인 `$O(n)$` 또는 블록 `$$...$$` 으로 표기
- 간단한 거듭제곱·지수 표기는 유니코드 위첨자 문자를 인라인에 사용 가능

  | 문자 | 코드포인트 | 문자 | 코드포인트 |
  |---|---|---|---|
  | ⁰ | U+2070 | ⁽ | U+207D |
  | ¹ | U+00B9 | ⁾ | U+207E |
  | ² | U+00B2 | ⁺ | U+207A |
  | ³ | U+00B3 | ⁻ | U+207B |
  | ⁴–⁹ | U+2074–U+2079 | | |

  예: `2³²` → 2³², `n²` → n²

### 4-5. 제목 대소문자

- `#`, `##`, `###` 등 헤딩: **Title Case** — 모든 단어 첫 글자 대문자
  - 예외: 접속사·전치사·관사(and, or, of, in, to, a, an, the ...) 는 소문자 유지
  - 예: `## Arithmetic Operations in C` O, `## Arithmetic operations in c` X
- 한국어 헤딩은 별도 대소문자 규칙 없음 (혼용 시 영어 부분은 위 규칙 적용)

### 4-6. 문장·목록·강조·인용

| 요소 | 규칙 |
|---|---|
| 일반 문장 | 첫 단어만 대문자, 나머지 소문자 (고유명사·언어 표준 표기는 예외) |
| 목록 항목 | `-` 불릿 사용; 간결한 구(phrase) 형태는 마침표 생략 가능 |
| 강조 | `**bold**` 사용 (이탤릭은 §4-1 예약 용어에만 사용) |
| 인용·전문 문장 | `>` 블록쿼트 사용; 온전한 문장이지 목록 형식 아닌 것 |
| 표 셀 | 일반 문장과 동일 — 첫 단어만 대문자 |

### 4-7. 유용한 특수 문자

강의 자료에 자주 쓰이는 특수 문자 목록:

| 문자 | 용도 |
|---|---|
| → ← | 흐름·변환 방향 표시 |
| ≠ | 같지 않음 |
| ± | 양·음 부호 |
| × ÷ | 곱셈·나눗셈 기호 |
| ≡ | 항등(equivalence), 정의 |
| ⎮⎮ | 절댓값 기호 |
| ` ` (U+2009) | 얇은 공백 (thin space) — 수식 구분 등 |
| § | 절(section) 번호 표시 |

### 4-8. 레퍼런스 인용 형식

표준 규격·섹션을 인용할 때 아래 형식을 따릅니다.

```
ANSI C (C89) §3.2.1.5 — "Floating Promotions"
ANSI C (C90) §6.2.2.1 — "Characters and Integers"
```

- 표준 이름: `ANSI C (C89)` / `ANSI C (C90)` / `ISO/IEC 9899:1990`
- 섹션 번호는 `§` 뒤에 점으로 구분된 번호 (예: `§3.2.1`)
- em dash(`—`) 뒤에 섹션 제목을 큰따옴표로 표기
- 본문 인라인 인용은 backtick 없이 일반 텍스트로, 강조 필요 시 bold 사용

## 5. 코드 정확성 체크리스트

### 5-1. ANSI C 문법 위반

- [ ] `//` 단행 주석 → `/* */` 로 교체
- [ ] for 루프 내 변수 선언 (`for (int i = 0; ...)`) → 블록 선두 분리 선언
- [ ] `_Bool`, `true`, `false`, `<stdbool.h>` 사용 → ANSI C 불가
- [ ] `inline`, `restrict` 키워드 → ANSI C 불가
- [ ] 가변 길이 배열(VLA: `int arr[n];` where `n` is a variable) → ANSI C 불가

### 5-2. 정수 나눗셈 / 타입 변환 관련

- 정수 피연산자 간 나눗셈 → 소수 부분 버려짐 명시 필요
- 정수와 실수 혼용 시 → 정수가 실수로 승격되는 규칙 확인
- `char` 타입의 부호 여부(signed/unsigned)는 구현 정의(implementation-defined) 명시 필요한 경우 표기

### 5-3. 미정의 동작(Undefined Behavior) 관련

- 미초기화 변수 사용 → UB, 코드 예시에서 의도하지 않은 경우 수정 또는 주석 추가
- 배열 범위 초과 접근 → UB
- `char` 형 변수로 `EOF` 판별 → 플랫폼에 따라 오동작 가능, `int` 타입 권장
- 부호 있는 정수 오버플로우 → UB

### 5-4. 함수 관련

- `main` 함수의 반환 타입은 `int` (ANSI C에서 `void main()` 은 비표준)
- 함수 선언(prototype) 없이 함수를 정의보다 앞서 사용 → 컴파일 오류 또는 암묵적 선언(C89에서 `int` 반환으로 가정, 위험)
- 함수 선언과 정의의 반환 타입·매개변수 타입 불일치 확인

### 5-5. 문자열 관련

- `char` 배열에 문자열 저장 시, 배열 크기 = 문자열 길이 + 1(널 문자) 이상이어야 함
- 널 문자(`'\0'`) 생략 → 미정의 동작

### 5-6. 코드 완전성

- 설명을 위한 예시 코드 스니펫(e.g., 구문 형식 설명, 일부러 오류를 보여주는 단편)을 제외하고, **모든 코드는 그 자체로 완전해야 함**
  - 완전한 코드 = `#include`, `main` 함수 포함 여부 등 컴파일·실행이 가능한 수준
  - 예시 스니펫 여부가 불명확한 경우 불완전한 코드로 보고

- **슬라이드 분할 코드** — 슬라이드 지면 한계로 하나의 코드가 여러 슬라이드에 걸쳐 나뉠 수 있음
  - 앞 슬라이드 코드의 **마지막 줄**이 `/* continues on next slide */` 이면, 해당 코드는 다음 슬라이드로 이어짐
  - 뒷 슬라이드 코드의 **첫 번째 줄**이 `/* continued from previous slide */` 이면, 해당 코드는 앞 슬라이드에서 이어받은 것임
  - 위 두 주석이 쌍을 이루는 분할 코드는 **불완전한 코드로 보고하지 않음** — 슬라이드를 순서대로 이어 붙이면 완전한 프로그램이 되어야 함
  - 분할 코드 체인의 중간·끝 슬라이드에서 `/* continued from previous slide */` 없이 코드가 뚝 끊기거나, `/* continues on next slide */` 없이 미완성 상태로 끝나는 경우는 불완전한 코드로 보고

- 코드 블록 내에 아래 문구가 포함되어 있으면 **잘못 붙여넣은 코드**이므로 반드시 보고:

```
DO NOT CONTAIN THIS LINE IN THE MARKDOWN
```

## 6. 내용 정확성 체크리스트

### 6-1. 자료형 크기·범위

- `int`, `long` 등의 크기는 플랫폼 의존적(platform-dependent) — 고정값으로 단정짓지 말 것
  - 단, 표에 크기를 명시할 경우 "LP64 기준" 등 조건을 병기
- `sizeof(int) <= sizeof(long)` 은 C 표준이 보장하는 관계 — "`long` 이 `int` 보다 작을 수 있다"는 잘못된 설명
- `char` 는 1바이트(8비트) = 256가지 값 표현, ASCII는 0~127(128가지) — 혼동 금지

### 6-2. 연산자

- 대입 연산자(`=`) 우선순위 < 비교 연산자(`!=`, `==`, ...) — `(c = getchar()) != EOF` 괄호 필요 이유 설명 시 정확히 기술
- 후위 증가 `i++` 와 전위 증가 `++i` 의 평가 순서 차이 명시
- 논리 연산자 단락 평가(SCE, short-circuit evaluation) — `&&`, `||` 에 적용

### 6-3. 스코프·링키지·저장 기간

- 지역 변수(자동 변수, automatic variable): 블록 진입 시 생성, 블록 종료 시 소멸
- 외부 변수(external variable): 프로그램 실행 시 생성, 종료 시 소멸 → **0으로 자동 초기화**
- 지역 변수는 **쓰레기 값(indeterminate value)** 으로 초기화됨 (자동 초기화 없음)
- `static` 지역 변수: 자동 초기화(0), 함수 호출 간 값 유지
- `extern` 선언은 정의가 아님 — 외부 정의를 참조하는 선언

### 6-4. 전처리기

- `#define` 치환은 단순 텍스트 치환 — 세미콜론 포함 주의
- `#include <...>` vs `#include "..."` 차이: 표준 라이브러리 경로 vs 사용자 정의 경로
- 매크로 함수 인수에 부작용 있는 표현식 전달 시 의도치 않은 동작 가능

### 6-5. 포인터

- `*` 는 선언 시 포인터 선언, 표현식에서 간접 참조(indirection) 두 가지 역할
- `&` 는 주소 연산자(address-of operator)
- 포인터 산술: `p + n` 은 `n * sizeof(*p)` 바이트 이동
- 배열 이름은 첫 번째 요소를 가리키는 포인터로 사용됨
