### 움직임 감지 원리

1. 연속된 두 프레임의 차이를 계산
2. 차이가 임계값을 넘는 픽셀 수를 집계
3. 그 수가 기준을 넘으면 "움직임 발생"으로 판정

- 조명 변화에 의한 오탐을 줄이려면 임계값 조정과 노이즈 제거가 필요

## 실습 10 - 프로젝트 진행 방법 (How to Proceed)

- 한 번에 완성하려 하지 말고 **동작하는 최소 버전부터** 만들 것

| 단계 | 목표                       | 확인 방법           |
| ---- | -------------------------- | ------------------- |
| 1    | 카메라에서 프레임 1장 저장 | 이미지 파일 확인    |
| 2    | 연속 캡처와 프레임률 측정  | 초당 프레임 수 출력 |
| 3    | 두 프레임 차이 계산        | 차이 값 출력        |
| 4    | 임계값으로 움직임 판정     | 로그 확인           |
| 5    | LED·저장·로그 연동         | 동작 확인           |
| 6    | 웹으로 영상·이벤트 제공    | 브라우저 확인       |

### 각 단계마다

- **커밋**하고, 동작하는 상태를 남길 것
- 다음 단계에서 문제가 생기면 되돌아갈 지점이 됨

> 8장에서 배운 "롤백할 방법을 먼저 준비하라"는 원칙이 개발 과정에도 적용됨

## 실습 10 - 과제 (Tasks)

<!-- IMAGE [스크린샷] 완성된 미니 CCTV 웹 UI 화면과 장치 설치 사진 (img/24-cctv-result.png) -->

1. 웹캠 영상을 웹 브라우저에서 확인할 수 있도록 구현
2. 움직임 감지 시 사진을 저장하고 LED로 표시
3. 감지 이력을 시간과 함께 기록
4. CMake로 빌드하고, 크로스 컴파일로 arm64 바이너리를 생성

### 고찰 항목

- 프레임률과 감지 정확도의 관계
- 오탐(false positive)이 발생한 상황과 그 원인
- SIMD를 적용한다면 어느 연산에 적용하겠는가(이론 9주차)
- 이 시스템을 제품화한다면 어떤 라이선스 문제가 발생하는가(이론 13주차)

## 실습 전체 정리 (Summary)

- **실습 01~02**: GPIO 디지털 입출력과 상태 기계
- **실습 03~05**: 센서 프로토콜 — 단선, SPI/ADC, 펄스 폭 측정
- **실습 06**: 센서 통합과 웹 서비스
- **실습 07~08**: 멀티미디어 입력
- **실습 09**: 크로스 컴파일
- **실습 10**: 전체 통합 프로젝트

### 반복해서 강조한 원칙

1. **자원은 반드시 해제** — RAII로 구조적으로 보장
2. **반환값을 항상 확인** — 하드웨어는 자주 실패함
3. **로직과 하드웨어 접근을 분리** — 순수 함수는 테스트할 수 있음
4. **데이터시트를 근거로** — 타이밍과 전압은 추측하지 말 것

## 한 학기 정리 (Course Summary)

<!-- IMAGE [로드맵] 1장 개론부터 14장 미니 CCTV 까지의 학습 경로 다이어그램 (img/17-course-roadmap.png) -->

### 하드웨어 제어

- GPIO 디지털 입출력, 상태 기계, 센서 프로토콜(단선·SPI·펄스 폭), 카메라·마이크

### 소프트웨어 엔지니어링

- CMake 빌드, 크로스 컴파일, 라이브러리 설계와 ABI, 최적화와 SIMD
- `volatile`과 동시성, 모델 보안, CI/CD, 라이선스, 배포

### 관통하는 원칙

1. **측정하고 나서 최적화할 것**
2. **자원은 반드시 해제할 것** — RAII로 구조적으로 보장
3. **하드웨어는 실패한다** — 반환값 확인, 재시도, 범위 검사
4. **로직과 하드웨어를 분리할 것** — 그래야 테스트할 수 있음
5. **자동화하고, 되돌릴 방법을 먼저 준비할 것**

## 14장 정리 (Summary)

- 미니 CCTV는 한 학기 전체 내용이 모이는 **통합 프로젝트**
- 움직임 감지의 원리는 **연속 프레임의 차이**를 임계값과 비교하는 것
  - 조명 변화로 인한 오탐을 줄이는 것이 실질적인 과제
- 개발은 **동작하는 최소 버전에서 시작해 단계적으로 확장**
- 각 단계를 커밋해 되돌아갈 지점을 남길 것
- 제품화를 고려한다면 성능(SIMD·전용 SoC), 보안(모델·무결성),
  라이선스(AGPL 등)를 함께 검토해야 함
